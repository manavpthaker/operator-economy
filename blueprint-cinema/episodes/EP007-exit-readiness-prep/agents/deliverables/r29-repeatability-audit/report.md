# R29 repeatability audit

Read-only architecture review, 2026-09-10. Scope: existing direction schema, CLI/compiler, state approval mechanics, targeted tests, and the September 8 context-direction implementation record. This report does not approve media, promote R29, or advance a gate.

1. **Reusable directing requirements exist in executable code.** Schema 1.2.0 requires authored scene context, the reason for each shot, entry/exit triggers, protected holds, alternatives, and review questions. The compiler preserves these fields plus exact shot recipes; director packets include adjacent narration. Validation checks exact word cues, referenced objects/assets, picture/audio compatibility, explicit motion changes, and contiguous declared shot intervals. It can require a reason for motion; it cannot judge whether the reason adds anything for the audience. Sources: `schemas/scene-directions.schema.json`, `src/blueprint_cinema/validation.py:705`, `src/blueprint_cinema/scene_prompts.py:299`.

2. **Hash-bound approval and deterministic packet generation are implemented, but separate.** State approvals pin supplied artifacts, reject stale inputs and skipped stages, and invalidate downstream approvals on upstream reapproval. Build manifests bind the direction file and generated prompt bytes. The CLI requires a current approved visual plan before compiling and explicitly leaves production state unchanged. It does not create a creative approval merely because direction validates. Sources: `src/blueprint_cinema/state.py:51`, `cli.py:352`, `scene_prompts.py:385`.

3. **The experimental preview is not yet a compiler-driven production instance.** At audit time this EP007 folder has no canonical `scene-directions.json`, `production-state.json`, `input-lock.json`, or `visual-plan.json`. The existing schema requires 1920×1080 at 30 fps; the accepted review work has used 1280×720 at 24 fps. The schema and build prompt both still hardcode 30 fps. The contract and September 8 report explicitly identify the full HyperFrames/Resolve state-machine migration as unimplemented. Therefore the experiments supply a reusable reference and decision history, not proof that a next episode can already be built automatically through this path. Sources: schema frame contract lines 79–86, compiler implementation rule 2, `references/SCENE-DIRECTION-CONTRACT.md:143`, `review/context-direction-update-20260908.md`.

4. **Declared coverage is checked; actual visible coverage is not.** `validate_scene_directions` catches gaps and overlaps between authored shot times and coverage through the declared end (0.01-second tolerance). It does not execute the HyperFrames timeline or compare media end times with opacity/visibility. A video ending while the animation remains hidden can therefore pass these checks. No rendered-frame black-screen/active-layer regression exists in the three reviewed test modules. Human expression appropriateness and whether an animation improves understanding also remain review judgments. This is the relevant automation gap exposed by the recent blank interval, not a failure of the declared-interval check.

5. **Narrow next step: bind the accepted checkpoint, then connect one vertical slice.** Preserve R29's exact accepted files, narration ranges, source clips, rejected choices, and reasons in a single episode checkpoint. Use it to define a reviewed recipe with explicit cut triggers and visible-layer intervals. Before describing the pipeline as automated, connect that one recipe to the contract/compiler and add a real timeline regression around every cut (including the repaired owner→animation boundary), resolving the 24/30 fps mismatch deliberately. Keep audience-value and performance approval human. This is a recommendation; no migration or shared-code change was performed in this audit.
