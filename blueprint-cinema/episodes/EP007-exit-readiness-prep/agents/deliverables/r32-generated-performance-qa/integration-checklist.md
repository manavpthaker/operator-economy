# R32 output review and integration checklist

Preparation only, 2026-09-11. Actual new outputs have not been provided or inspected. This packet creates no service, upload, integration or approval authority.

1. Receive each actual local output path and SHA-256 from root. Verify the exact bytes before inspection. Stop on missing or mismatched files; do not poll services, regenerate, or overwrite prior QA.
2. Run `qa_outputs.py inspect --take <take> --stage <native|restored> --input <exact-path> --sha256 <exact-hash>`. Takes: `post-title-lens-contact`, `question-pensive`, `buyer-reaction`. Run native and restored as separate artifacts. Use a new `--tag` for an explicitly issued revision.
3. Inspect source codec, dimensions, frame rate, duration, start PTS, full decode, cadence and repeated frames. Decode success and distinct frames do not prove natural motion. Check source handles against the **measured new offset**, not R31's values. If insufficient picture remains for the complete original narration, stop; do not stretch, repeat spoken frames, trim words, or transfer another take's source inpoint.
4. For restored avatars, verify the pinned original narration and measure independent early/middle/late waveform insertion. A low correlation or search-boundary result cannot supply an integration offset. Treat the nearest source frame and quantization residual as review data. Compare word/viseme transitions at actual speed before any lip-sync conclusion or corrective shift. Native generated speech is not the final voice.
5. **Post-title:** compare exact accepted V5 identity, wardrobe, study, wide hand coverage and credible anatomy. Through “and the one number…,” inspect near-lens attention, ordinary blinks, no upward/sideways gaze break, and quiet conversational emphasis. Look for changing gestures with rest and a natural ending; do not require one prescribed gesture count or a held stare.
6. **Question:** compare beginning versus the later turn. Near “then who is getting paid,” look for a subtle reduction of the half-smile, slight inner-brow gathering and settled hands while retaining easy articulation and near-lens attention. The expression should develop with the question. Flag a fixed expression, anger, pronounced worry, deep frown, brow lifting, staged chin support or lip distortion. Inspect the complete “closeable” and a quiet mouth endpoint. These are requested review criteria, not claims that a prompt achieved them.
7. **Buyer:** wait for root's exact buyer request, reference and output pins before judging directed eye-line, expression, reaction timing or spoken/silent mode. The current REQUESTS input contains only the two avatars. Script preparation covers general probe/decode and early/middle/late/full-frame contact evidence; it does not invent buyer-specific performance criteria.
8. Root retains R32's accepted cuts, source-time continuity, original soundtrack and existing final question hold when integrating. Check the wide-to-close boundary, speech ending and outgoing transition in the actual runtime. Do not reuse a mouth-performance source against different words, clone spoken frames or treat the prior native question endpoint concern as an unresolved defect in the already reviewed restored R31 endpoint.
9. Review synchronized normal-speed output, then targeted frame samples. Report measured facts separately from sampled observations and subjective performance judgments. Record actual pins and playback limits. Return findings to root; do not claim owner acceptance, change gates, or authorize further takes.

The local QA script writes only inside this owned folder. `prepare` verifies the six baseline pins; later `inspect` verifies the explicitly supplied output hash and the immutable original-audio pin. It does not assume that runtime files remain unchanged while root integrates. The baseline files are preparation context, not a claim about a later live runtime.
