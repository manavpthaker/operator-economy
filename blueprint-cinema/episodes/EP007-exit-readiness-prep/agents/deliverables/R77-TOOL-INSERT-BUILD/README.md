# R77 tool insert build packet

This packet is build-ready after root supplies real capture selections. It contains no generated or simulated software UI. Only files inside this packet may be written by the builder.

1. Copy `selection-template.json` to a root-owned selection file and fill the actual absolute capture path, SHA-256, source-in seconds, exact output-frame count and optional source-pixel crop for each selected segment. S15 segments must total 284 frames; S16 must total 655. Root must visually approve each crop and range. `crop: null` contains the full window; it may be too small to read if the captured window is tall.
2. Run `python3 prepare.py --selection /absolute/path/selected-captures.json`. This creates isolated `projects/s15` and `projects/s16`. Existing project directories are refused to protect prior outputs. The original accepted clips and master are hash-checked before use. Actual capture ranges are normalized to 24 fps without speed changes; insufficient frame count fails. No artificial tail hold is added.
3. Perform the current HyperFrames CLI check under each new project: `npx --yes hyperframes@latest upgrade --project . --check`. If it reports a newer version, apply the project upgrade and validate the updated project according to the installed skill. The proposed package pins the currently used 0.8.46; do not change accepted legacy projects.
4. Check source readability, all internal capture cuts and the two insertion boundaries using `npx --yes hyperframes@0.8.46 check . --strict --at <times> --json --snapshots`. Use the updated version instead if step 3 upgraded it. S15 seam samples: 25.291667, 25.333333, 37.125000, 37.166667. S16 seam samples: 8.833333, 8.875000, 36.125000, 36.166667. Also inspect the capture actions and final frame.
5. Root may render for the already authorized review. `prepare.py --selection ... --render` combines initial preparation, strict check, render and decode using the 0.8.46 pin, only when the version check confirms that pin current. For an already prepared project, use the normal CLI directly: `npx --yes hyperframes@0.8.46 render . --output qa/s15.mp4 --quality looks --workers 1` (S16 uses `qa/s16.mp4`). The script is not a retry manager and will not overwrite its prepared project.

Root owns the actual selection, source capture rights/provenance, full playback check, review player, source-map entry, decision log, acceptance and integration. This proposal does not alter any shared log, accepted artifact, narration, episode status or final Resolve timeline.

`python3 prepare.py --describe` performs only edit-interval arithmetic and prints the plan. It makes no media or project files. Source selection is intentionally absent until actual recordings have been inspected.
