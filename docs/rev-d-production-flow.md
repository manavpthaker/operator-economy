# Rev D Production Flow

Rev D treats the storyboard as the production contract between an approved script and media generation. A render must not invent the visual argument at the last minute.

## Required episode artifacts

Each `studio/originate/<slug>/` directory carries:

- `storyboard.json`: timed screens with `narrative_state`, `camera`, `footage_role`, `visual_intent`, `score_state`, and concrete sourcing queries.
- `storyboard_review.html`: the operator-facing edit board generated by `storyboard_review.py`.
- `footage_manifest.json`: reviewed footage, rights metadata, trim points, crop, and focal position.
- `music_brief.json`: episode-specific lane, motifs, exclusions, Flow project/session, and review status.

## Sequence

1. Lock the factual script and voice performance.
2. Build the five-state waveform: `peril → absurdity → reversal → build → agency`.
3. Run the hand-tuned storyboard builder, pacing pass, and storyboard review generator.
4. Approve visual intent before sourcing. Prioritize original screen capture and real operating artifacts; use licensed stock only for exact human actions and outcomes.
5. Review footage candidates and write approved selections into the manifest. Unresolved B-roll remains a visible render blocker.
6. Generate two instrumental score candidates inside the **Operator Economy** Google Flow Music project. Record the session URL; do not silently select a candidate.
7. Regenerate the complete VO batch with the configured narrator. Never mix narrator IDs.
8. Render the cold-open preview, then the complete episode. Run edit, footage, facts, graphics, and release gates.

## Opening contract

Story motion starts at frame zero. The fixed 2.4-second OE sting overlays motion at 0:02, followed by a 1.6-second episode-title lock. By 0:30 the viewer must have seen a human action, a market force or proof artifact, and a glimpse of the counter-system.
